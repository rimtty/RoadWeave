# RoadWeave LVGLレンダリング移植

デザインの構造・情報・動きを、PCとESP32で共用するLVGLのCコードへ移す。実ブラウザの参照画像と実際のLVGL描画を比較し、操作と状態更新まで検証する。

以下のコードパスとコマンドはリポジトリルート基準。既存実装・設定を確認して使い、過去の成功結果を今回の検証結果として報告しない。ユーザーが指定した範囲に合わせて必要な工程を実行する。

## 最初に参照するもの

- [Windowsシミュレーター手順](../../../firmware/experiments/ui_lvgl/pc/README.md)：起動、操作、画像候補、回帰テスト。
- [13〜16番の移植実例](../../../firmware/experiments/ui_lvgl/pc/DOT_STUDIES.md)：再現方針、タッチ設計、比較画像の生成、検証範囲。ここでの画面番号・寸法・循環操作は実例であり、別画面への固定要件ではない。
- [Web UIラボ](../../../design/web-poc/README.md)：カタログと動作デモ。必要な画面のソースだけを追加で読む。
- フォント変更時は[フォント生成手順](../../../firmware/experiments/ui_lvgl/main/fonts/README.md)、実機ビルド時は[開発環境](../../../docs/development-environment.md)も読む。

## 1. 移植するデザインと状態を特定する

1. Gitの作業状態を確認し、既存の変更と今回の対象を把握する。対象のカタログ番号、画面、動作デモを特定する。サムネイルだけからUX全体を推測しない。
2. Webを実ブラウザで描画し、ソースとDOM/SVGの両方から配置、余白、色、輪郭、文字、字形、動きを確認する。静止画像だけでなく対象の操作後の状態も見る。
3. 論理解像度への変換方針を決める。現行シミュレーターは240×320 / RGB565。13〜16番では300×400のWebカードを80%に正規化した。新しいデザインでは縮小か再配置かを判断し、元の情報階層を保つ。
4. WebとLVGLで比較するデータと時刻を固定する。待受、RX、TX、BUSY、ミュート、位置未更新、通信断、人数・距離の境界値から対象に必要な状態を選ぶ。
5. 参照画像とソースの版を残す。既存の `pc/capture-web-reference.mjs` は13〜16番用なので、新しい対象にはセレクター・状態・出力名を合わせる。`pc/reference/source.json` のようにソースのハッシュも記録する。

デザイン忠実度の修正と、視認性を改善するデザイン変更を区別する。省略・文字拡大・レイアウト変更が必要なら理由を示す。対象外の詳細画面や音声制御まで無断で範囲を広げない。

## 2. 画面遷移と入力を設計する

実装前に、画面の階層、左右・上下の役割、端で循環するか、戻り先、遷移後に保持する状態を短く説明する。既に指定された方針はそのまま使い、通常の実装判断で承認待ちにしない。

- 同階層の画面巡回と詳細画面から戻る操作を分けて考える。
- 指の移動方向と遷移先を明記し、1操作につき1遷移にする。
- 短距離、縦・斜め、長押し、画面外、フォーカス喪失、操作中の画面変更を扱う。
- ズーム後も論理座標で判定する。画面を送る操作で意図せずPTT/TXが始まらないようにする。

13〜16番の例は左で次・右で前、4画面循環、横40論理px以上・横が縦の1.5倍以上・1秒以内、解放時に判定。しきい値と循環は新しい画面の用途に応じて決める。

## 3. 共通LVGLコードで再現する

| 場所 | 変更の役割 |
|---|---|
| `design/web-poc/app/explore/collection.tsx`、`explore.css`、`demo/graphics.tsx`、`demo/model.ts` | デザイン、字形、状態の参照元 |
| `firmware/experiments/ui_lvgl/main/ui_screens.h`、`ui_screens.c` | 共通モデル、画面ID、生成・切替API |
| 同 `main/ui_dot.c`、`ui_dot.h` | 13〜16番のネイティブ描画・状態・スワイプの実例 |
| 同 `main/ui_simulation.c`、`ui_simulation.h` | 再現可能な模擬データと時刻 |
| 同 `main/ui_main.c`、`Kconfig.projbuild` | ESP-IDF側の初期化と画面選択 |
| 同 `pc/main.c`、`pc/scenarios.c`、`pc/dot_tests.c` | SDL入力・表示、固定シナリオ、操作検証 |
| 同 `main/CMakeLists.txt`、`pc/CMakeLists.txt` | 両ターゲットがコンパイルする共通ソース・フォント |

図形・文字・アイコンをLVGLオブジェクトまたは描画APIで構築し、データ更新に追従させる。画面全体のスクリーンショットを貼って移植完了にしない。PC専用の画面コピーを作らず、液晶・SDLなどの初期化だけを分離する。

- フォントのサイズだけでなくウェイトと字形を合わせる。可変フォントの既定ウェイトがWeb指定値と同じとは限らない。必要なウェイトを確定してからLVGL用に変換する。
- 日本語サブセットは実際の全表示文字列から生成し、欠けを画像で確認する。生成Cとライセンスを残す。通常ビルドにフォント取得・変換を要求しない。
- アニメーションは模擬時刻で再現・停止できるようにし、変化領域を適切に無効化する。古い／切断中の位置を確定値として見せないなど、表示の意味も移す。
- 新しい画面IDは既存の列挙・ループとの互換性を確認する。新シナリオは `pc/scenarios.c`、`pc/CMakeLists.txt`、`firmware/scripts/ui-sim.ps1` のValidateSetと一覧へ登録する。

## 4. 描画と操作を繰り返し検証する

1. **参照との比較**：固定データのLVGL PNGを生成し、同じ論理解像度のWeb画像と並べる。配置、字形、情報の欠落、重なり、色、状態を確認して修正する。WebとLVGL間のRGB565量子化やラスタライズ差は説明し、配置不一致を誤差として隠さない。
2. **LVGL回帰テスト**：意図した描画と判断した候補のみ基準画像へ登録する。現行のLVGL同士の比較は許容差0。テストを通す目的で無条件に基準を更新しない。画像不一致と基準欠落が正しく失敗し、基準を自動生成しないことも維持する。
3. **状態・操作テスト**：左右往復、端、無効ジェスチャー、キャンセル、状態保持、長い数値、ミュート・通信断などを対象に応じて確認する。動く領域以外の画素が維持されることや、古い距離を書き換えても表示が変わらないことなど、意味のある性質を検証する。
4. **実SDL表示**：dummyドライバーの自動テストに加え、Windowsの実ウィンドウを起動する。利用可能なWindows操作ツールとそのスキルに従い、マウスドラッグ、キー、倍率変更、停止・再開、PNG保存を実際に確認する。見た目と入力を確認できなかった項目は未検証と明記する。
5. **実機向けビルド**：共通C・ヘッダー・フォントを変更したらESP-IDFでも対象画面を含めてビルドする。`firmware/scripts/enter-idf.ps1` と既存手順を使い、Kconfigの選択、アプリ領域、リソース増加を確認する。PC描画やビルド成功を、実機FPS・RAMピーク・SPI転送・物理タッチの検証と混同しない。

描画欠けは、LVGLの論理バッファ、SDLの表示面、操作ツールのキャプチャを切り分ける。論理PNGが正常でも実ウィンドウの正常性は確定しない。必要なら既存 `pc/main.c` の `SDL_RenderReadPixels` による検証を使い、複数のアニメーション位相と状態遷移で表示画素をRGB565バッファと比較する。キャプチャ1枚だけから原因や修正完了を断定しない。

## コマンドの入口

```powershell
# ビルド、画像候補の生成（対象名は置き換える）
.\firmware\scripts\ui-sim.ps1 -Action Build
.\firmware\scripts\ui-sim.ps1 -Action Capture -Scenario dot13

# pc/build/candidates の画像を確認し、意図した結果の場合だけ登録
.\firmware\scripts\ui-sim.ps1 -Action AcceptBaselines -Scenario dot13
.\firmware\scripts\ui-sim.ps1 -Action Test

# 等倍の実ウィンドウ。静止比較には -Paused を付ける
.\firmware\scripts\ui-sim.ps1 -Scenario dot13 -Zoom 1
```

複数画面を変更した場合のみ必要な範囲で `-All` を使う。結果と差分は `firmware/experiments/ui_lvgl/pc/build/results/`。13〜16番のWeb比較生成は実例ドキュメントを参照する。スクリプトのRun / Build / Test / Captureは、同じcheckoutの実行中シミュレーターを終了して再ビルドするため、検証後に対象画面を再起動する。

## 今回得られた注意点

- `-Zoom 1` は論理解像度に対する倍率。WindowsのDPI拡大後のウィンドウ寸法と、240×320の保存PNGを混同しない。
- SDLの倍率変更で同じ論理解像度でもバッファが再確保される。現行実装の解像度変更イベントでの全面無効化を維持し、固定部分が消えないことを確認する。
- Windowsの遠隔操作ではキー押下でなく `SDL_TEXTINPUT` のみ届く場合がある。両方を受ける場合は二重実行を防ぎ、フォーカス喪失で押下状態を解放する。
- カスタム描画の背景・不透明度と無効化領域を正しく定義する。背景指定だけで全種類の描画欠けが直ると一般化しない。
- 小さい補助文字の忠実な再現と、実機での読みやすさは別に評価する。

## 引き渡し

対象デザインと再現範囲、変更の理由、比較画像、実施したテストと結果、未検証の実機項目を示す。表示確認を求められている場合は指定倍率のSDLを起動して引き渡す。既存の承認と作業範囲に従い、コミット・push・マージ・USB書き込みをこのスキルの自動工程として追加しない。
