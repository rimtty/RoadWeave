# voice_udp 初回計測（2026-09-06、XIAO 2.4 GHz Wi-Fi を HaLow 代役、**アンテナ未装着**）

構成: XIAO ESP32S3（内蔵 2.4 GHz Wi-Fi、**U.FL アンテナ未装着**）→ AP → Mac（`tools/rwp_peer.py echo`）→ 折り返し。
I2S mic 未接続（DIN 浮き = 無音フレーム）。IMA-ADPCM 20 ms、RWP/UDP、50 packet/s、送信常時。
firmware: `firmware/experiments/voice_udp`（commit 時点の版は mouth-to-ear の測定に欠陥あり、下記）。

## 結果

アンテナなしのため、リンクは接続直後の約 14 秒だけ健全で、その後は秒単位の遅延と大量ロスに崩れた。
**健全な区間の値だけを設計参考にする。**

| 区間 | RTT avg / max（1 秒窓） | ロス | jitter buffer | 備考 |
|---|---|---|---|---|
| 接続後 0〜14 s | 26〜59 ms / 68〜156 ms | ほぼ 0（50/s 中 47〜52 受信） | 40 → 80 ms（underrun 2 回で成長） | mouth-to-ear の表示値は 27〜49 ms だが測定欠陥あり |
| 14 s 以降 | 300〜2,900 ms | 30〜90% | 80 ms 張り付き、gap/underrun 多発 | アンテナなしの限界。設計参考にしない |

参考: 最初の 60 秒試験（jitter buffer 修正前）では depth が 20 ms に張り付き、underrun 68 回・gap 129 回。

## 分かったこと・直したこと

1. **jitter buffer の適応が late packet だけを見ていた**。Wi-Fi のバースト遅延では late ではなく underrun として現れるため、深さが増えなかった。
   → underrun でも +1 frame、直近にトラブルがあれば 10 秒は縮小しない（`shrink_holdoff_ms`）。host test 追加。
2. **RTT 統計が起動からの累積平均**で、初期の乱れを引きずった。→ 1 秒窓の平均/最大に変更。
3. **mouth-to-ear の測定が誤り**。「直近に受信したフレームの capture 時刻」を使っていたため、buffer 滞留分が抜けて RTT + 20 ms 程度にしか見えなかった。
   → jitter buffer に per-frame tag（capture_time）を持たせ、再生時に `now - tag` を取るよう修正（次回計測から有効）。
4. 2.4 GHz でも **アンテナなしでは 15 秒ともたない**。HaLow でも同じことが起きるので、WM6180 の Gate 3/4 で RF 終端・減衰器を先に確保する方針は正しい。

## 次回（アンテナ装着後）の手順

1. XIAO の U.FL に付属 2.4 GHz アンテナを装着。
2. `firmware/experiments/voice_udp` を flash、Mac で `python3 tools/rwp_peer.py echo`。
3. 60 秒以上取り、1 秒窓の RTT / mouth-to-ear / jb depth を記録。目標: mouth-to-ear p95 ≤ 150 ms（P0-B exit criteria）。
4. SPH0645 到着後（9/7）: `rwp_peer.py record mic.wav` で声を Mac に保存し、マイク品質を確認。

## 2 回目（同日、ルーター直近、アンテナ未装着、floor control + PLC 版、mouth-to-ear 測定修正後）

接続に 14 s、30 s に一度切断・34 s に再接続。**34〜94 s の 60 秒は安定**（50 packet/s、ロス 0、RTT median 8 ms / p95 12 ms）。

| 指標 | 値（安定区間 60 s） |
|---|---|
| RTT（Mac echo 往復） | median 8 ms、p95 12 ms、max 50 ms |
| mouth-to-ear（capture → 再生呼び出し、buffer 滞留込み） | median 100 ms、p95 160 ms |
| jitter buffer depth | 80 ms（初期の乱れで 40 → 80 に成長、hold-off で維持） |
| gap / underrun | 安定区間では gap 0、underrun +2（85 s 付近） |
| floor | TALK 維持、grant 1、busy 0、fail 0（coordinator 自身への in-process grant） |

内訳の目安: RTT 8 + jitter buffer 80 + I2S read/write の block 遅延 約 40 = 約 130 ms。実測 100〜160 ms と整合する。
**HaLow で RTT が安定していれば jitter buffer 40 ms で 60〜80 ms が見込め、P0-B の目標（p95 ≤ 150 ms）は射程内。**
Wi-Fi の初期 30 秒の不安定さはアンテナ未装着の影響で、設計参考にしない。

改善候補（P0-B 本実装で）: underrun 後の再 prefill で滞留が target を超えたまま hold-off 中は縮まない（85 s 以降 m2e 160 ms）。
再 prefill 時に target を超える分を捨てる、または hold-off 中も「target+2 frame 超」なら 1 frame だけ捨てる。

## 安全メモ

アンテナ未装着での連続送信は PA の負荷になる。計測後は無線を使わない smoke firmware（`firmware/`）へ戻した。
