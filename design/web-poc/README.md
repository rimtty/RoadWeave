# RoadWeave UI Lab

同じツーリングIP-PTT体験を、3つのデザインで比較するWeb PoC。音声、接続、参加者、位置はすべて仮データです。マイクや位置情報の権限は要求せず、実際の音声は送信しません。

## 3つの方向

| 方向    | 主画面             | デザインの狙い                                           |
| ------- | ------------------ | -------------------------------------------------------- |
| Circle  | 仲間と発話者       | 柔らかな色、アバター、穏やかな輪で声の存在を伝える       |
| Pulse   | 前後の距離         | 大きな数字、暗い背景、ライムのアクセントで瞬時に読み取る |
| Compass | 自分中心の相対位置 | 紺色のレーダーに仲間と発話状態を重ねる                   |

`#circle` / `#pulse` / `#compass` で各案へ直接移動できます。

## デザイン・スナップショット集

`/explore` に、60の異なる表現を操作して見比べるデモを追加しています。ホーム上部の「60のデザインを見る」からも移動できます。

01–12は人物・距離・レーダー・仮想地図・波形・モノクロ・隊列・高コントラスト・光・計器・タイル・無線機の各方向。13–16は黒地に白いドットと赤いアクセントを使った距離・音声・レーダー・計器一覧です。`/explore#dot-studies` でドット表現へ直接移動できます。

01–16で箱根・4人・AKIから受信中・前方120m・後方85m/240mのサンプルを共有します。地図と方位はレイアウト検討用の仮表示です。各カードに専用の操作デモがあり、01–03には既存の3案へ戻るリンクも残しています。ドット文字はSVGの円で描画し、外部フォントや画像に依存しません。

17–32は走行中の視認性を考えた追加案です。`/explore#driving-studies` から情報の優先順位と全16案を確認できます。17–20は発話者、21–24は前後の距離、25–28は待受・送信・切断・位置未更新、29–32は情報密度を減らしたドット表現。240×320の縦画面に比例して文字も拡大縮小します。設計根拠・サイズ・状態の意味・今後の評価は [driving-studies.md](driving-studies.md) にまとめています。

33–40はAMOLEDを想定したBlack Editionです。`/explore#amoled-studies` で直接移動できます。純黒 `#000000` の背景に、大きな名前・前後・距離・受信状態を表示。色面と発光する影を省き、白、青、紫、緑、琥珀、赤などの小面積のアクセントと情報配置の違いを比較します。全案が受信中のAKI・前方120mを示し、40は後方REN・85mも併記します。240×320の縦画面を論理基準とし、状態24px、主情報44–68px相当を目安に拡大縮小。図形のドット数字を使う39以外は通常の太い文字を採用しています。日光下での視認性・実消費電力は未測定で、AMOLEDへの実装や動作変更は含みません。

41–48はBlack EditionのPlay Seriesです。`/explore#pop-studies` で、黒にレモン・ライム・水色・ピンク・コーラル・ミント・紫を加えた8案を比較できます。モーターサイクル用UIの方向記号とアクセントカラーを参考に、縦画面の相対距離・発話者表示へ展開しました。41は距離を囲う弧、42は大きな前方記号、43は発話者カプセル、44は前後の二色表示、45は音声記号、46は四角いドット数字、47は声を囲む弧、48は二色のコーナー。全案で受信中AKI・前方120m、44は後方REN・85mも表示。音声を表す棒や弧は送受信に連動し、計測値や進捗を示すものではありません。背景は全案純黒、状態は24px、重要な名前や距離は主に44–72px相当、補助情報は14px以上の論理サイズを目安にしています。実機の視認性・消費電力は未測定です。

49–54はChroma / Curve Studiesです。`/explore#curve-studies` から確認できます。鮮やかな色、黒へつながる丸い切り欠き、S字の区切り、グラデーションの細い輪郭をUIの面・境界として使う6案です。49 Cobalt Cove、50 Mint Current、51 Fuchsia Dock、52 Citrus Nest、53 Prism Contour、54 Tidal Pair。名前と距離は単色の領域に大きく置き、同じ受信中AKI・前方120mを表示します。54は後方REN・85mも併記。240×320基準の操作デモで、写真・ノイズ背景・常時アニメーションは使用していません。色面の比率が高い案は省電力優先のBlack Editionと別に、実機の消費電力と日光下の見やすさを比較する対象です。

## 60案の操作デモと車列・GPS

一覧の「声・距離 / 車列・GPS」で全60案を一括比較できます。各カードの操作デモはその案の画面を拡大し、同じ状態のまま両画面を切り替えます。URLの例：

「1人で発話 / 2人で発話 / 3人で発話」で、全60案を同じ人数にまとめて切り替えられます。「初期状態」で各案の元の場面に戻ります。人数を選んでカードを開くと、その人数で操作を開始します。発話者の複数選択と距離を操作する対象の選択は、別々のボタンです。

- `/explore?demo=46` — Mint Pixelの操作デモ。
- `/explore?demo=46&screen=fleet` — 同じ案の車列・GPS画面。

操作できる項目は、仲間の同時発話（複数選択）、相対位置（−999〜999m）、走行の再生、送信先、参加・退出、通信接続、位置未更新、受信音量、ミュート、リセットです。PTTはマウス・タッチ・フォーカス中のSpace/Enterで長押し。自分を含め最大3人が同時に発話でき、受信中も260msの許可待ちを経て模擬送信します。3枠が使用中なら押したまま待機し、枠が空いたら許可待ちへ進みます。リリース、短押し、フォーカス喪失、ポインターキャンセル、画面切替、閉じる、切断、退出で送信・待機を解除します。本体のソフトウェアキーボードはありません。

2〜3人の発話時は各案の配色・曲線・ドット表現を引き継ぐ同時通話画面に切り替え、名前（55〜60は色名）・各人の距離・個別メーターを表示します。自分の送信も同じ画面で確認できます。車列画面は発話中の順位に下線を付け、フッターに発話人数を表示します。元のCircle / Pulse / Compassも同じ最大3人の方針で、仲間・ライド・レーダーの全画面に現在の話者を並べます。ミュートは受信音だけに作用し、使用中の発話枠は解放しません。IP音声ストリームの実際のデコード・ミキシングは今回のWeb PoCには含めていません。

車列・GPSは全60案に専用の配色・角・線・ドット設定を持ち、縦積み、地図優先、横分割、タイル、レーダーの配置を使い分けます。前から並ぶ4人の車列、自分の順位、各車への相対距離、地図マーカー、選択中の仲間の緯度経度を表示します。位置を変えると並び順とマーカーが更新され、GPSを拡大して確認できます。位置未更新や切断時は古い順位・距離・仲間のマーカーを表示しません。GPS座標と経路は計算された仮データで、実際の地図・GPS・音声・BLE通信は利用していません。

05/12の棒メーター、14のドット波形、26の送信メーター、45/47の声の表現に、状態連動のアニメーションを実装しています。待受・切断時に停止し、受信ミュートや音量0でも受信メーターが止まります。送信メーターは受信ミュートとは独立しています。OSの「視差効果を減らす」設定では静止表示になります。ドット文字は0〜9、未更新の「—」、3人の名前に対応し、距離スライダーで描画内容が変わります。

`npm test` は従来モデルに加えてPTT・位置・車列・GPS・色の整合性を検証します。`npm run test:studies` はHappy DOM上で実際の60案のReactコンポーネントを操作し、両画面・ドット数字・アニメーション適用条件・キャンセルを検証します。ブラウザ描画や実機の視認性を測定するテストではありません。

## 本体の文字入力と製品化前の検討

- 製品本体にソフトウェアキーボードは設けない。基本利用は名前入力なしで成立させる。
- グループ内のメンバーIDと識別色の対応を共有し、端末ごとに異なる色を割り当てない。接続し直しても同じ対応を保ち、退出で他のメンバーの色・順番を詰め直さない。色数の上限、重複、再参加、未登録端末は別途仕様化する。
- 人物ごとの図形による識別は採用しない。色帯・色面を使い、日光下や色覚差による識別性は実機で評価する。人数の上限や色が区別できない場合の扱いは別途検討する。
- 任意の表示名が必要な場合、停車中にスマートフォンアプリとBLE接続して設定する方式を、製品化前に別途検討する。ペアリング、対象端末の確認、保存先、グループへの共有範囲、アプリなし運用を設計する。今回はBLE／アプリ／名前同期を実装しない。
- 既存の操作デモにあるグループ名入力等は過去のUX検討用であり、最終製品の本体入力方式を示さない。今回の追記でそのデモの挙動は変更していない。

## 操作

- 左のデザイン選択で方向を切り替え。端末下部の「仲間・ライド・レーダー」または左右スワイプで画面切り替え。
- 右の「待受」にするとPTTを試せます。押して260ms後に仮の送信状態へ進み、離すと終了。短押し・切断・別画面への移動・フォーカス喪失で送信が残らない設計。
- 仲間の受信音に自分の送信を重ねられます。最大3人が発話中の場合だけ空き待ちに入り、押し直しは不要です。PTTを離せば自分の送信・待機を終了し、他の人の受信は継続します。
- アバターや名前を選ぶと、個別音量・消音・個別PTT。個別PTTは相手を選ぶだけでは送信せず、物理ボタンを想定したPTTで送信します。
- グループ設定でメンバー・全体音量・退出。参加からのデモ、グループ作成、空のグループにも対応。
- 20秒のデモは6場面を順に再生。端末を操作すると停止します。「動きを控えめに」とOSの動きを減らす設定に対応。

## 実行と確認

Node.js 22.13以上。

```sh
cd design/web-poc
npm ci
npm run dev -- --host 127.0.0.1
npm run typecheck
npm run lint
npm test
npm run build
```

Lintは作成したアプリ、状態モデル、変更したSliderを対象とします。テンプレートの未使用UI部品は対象外です。TypeScriptはプロジェクト全体を確認します。

車列画面のレイアウト回帰テストは、開発サーバーを起動した状態で `npm run test:fleet-layout` を実行します。インストール済みのChromeを使い、全60案の240・300・360px幅、390・320pxのモバイル画面、距離の変化・位置未更新・切断・地図拡大を描画して確認します。文字のはみ出し、文字同士の重なり、GPS番号の衝突を実際のブラウザ座標で検出し、レポートと各案の画像を `outputs/fleet-layout/` に保存します。接続先は `BASE_URL`、ブラウザチャンネルは `BROWSER_CHANNEL` で変更できます。DOMだけの操作テストは `npm run test:studies` です。

状態モデルのテストは、最大3枠・同時送受信・枠の空き待ち・送信許可前のリリース・切断・キャンセル後の参加コールバック・音量・位置の鮮度・文字数・デザイン切り替えを検証します。

同時通話は `npm run test:voice-mix` で確認します。比較ボード、全60案の2・3人受信、自分＋2人の同時送受信、最大3枠、押したままの空き待ち、リリース、ミュート、位置未更新、240・300・360pxの表示幅とモバイル表示を検証します。元の3案でも同時送受信と画面切り替えを操作します。画像とレポートは `outputs/voice-mix/` に保存されます。

## 確認範囲と残る検証

2026-09-06、Mac Chromeで3案の表示と390px/320px幅を確認。参加、作成、個別音量のキーボード変更、消音、個別PTT選択、短いPTT操作、切断時の送信抑止を操作して確認しています。

PTT長押しのタイマーは状態モデルと実装で確認していますが、実際の指での長押し、スワイプ、車内視認性、実機のキーイベントは別途受入確認が必要です。Webの表示・アニメーションはLVGLのFPS・メモリ・音声同時処理性能を証明しません。

WebMCPは対応環境のみ `read_roadweave_preview` と `set_roadweave_scenario` を登録します。今回のブラウザー接続はWebMCP検証能力を提供していないため、ツール契約の実行検証は未実施。通常のUI操作には影響しません。

## LVGLへ移すとき

- 状態モデル、表示文言、色、部品の配置を移植対象にする。CSSそのものは移植しない。
- Circleのアバターは円とラベル、声の輪は少数の輪郭にする。Pulseはラベル・バー・矩形を中心に構成。Compassは固定目盛りと小さな位置マーカーを分ける。
- 常時動かすのは発話マーカーなどの狭い領域。全画面のぼかしや影はWebの演出であり、実機では背景画像か単色へ置き換える。
- このプレビューの縮小表示は寸法の目安。実際の240×320パネル向けにはフォント・余白・描画領域を再配置して評価する。
- 走行中は物理PTTと音量操作を中心にし、グループ編集や細かな音量調整は停車中の操作として検討する。
- S3でOpus・無線・LVGLを同時に動かした実測を、P4などへ進む判断材料にする。

デザインの参考文脈はAppleの情報階層・直接操作・意味のある動き、およびXiaomiの大きな数字・柔らかい形状・状態遷移です。固有製品の画面や商標表現はコピーしていません。
